Separate bounded benchmark artifact, not production gameplay. Production Main,
main_scene and export defaults stay byte-identical to the base. No public
hosting, spending, security workaround, threshold, FPS or ordinary-laptop claim.
Combined548/550/551 acceptance remains open, with no objective-retirement link.

selected current source into temporary projects. Only those copies get a separate

Console and downloadable JSON stay inside the benchmark artifact. No adapter
is added to production. Renderer counters are not nodes drawn; eligibility is
not physics sleep. Results are relative diagnostics with observer overhead.

Before ready: verify normal production source/default export unchanged and

## Running

Requires Godot4.5.1 with official installed Web templates, Python3 plus the
`websocket-client` module and local Chrome. No account login or public hosting.

```
python3 tools/benchmarks/run_browser_gameperf.py \
  --prefold /path/to/clean-20be5d8 --current /path/to/clean-current \
  --godot /path/to/godot --chrome /path/to/google-chrome \
  --output /tmp/browser-gameperf/result.json
```

Both sources are copied, never edited. Template files remain local. The runner
writes benchmark provenance in the temporary export, imports, exports using the
separate preset, serves only127.0.0.1, starts local software Chrome, and uses
normal pointer events to press Start. Browser lifecycle is bounded and closed.
It verifies downloaded JSON equals the console result and saves OFF/DONE pixels.
Inspect those actual images before accepting the fixture. Do not treat successful
export or a JSON payload alone as visual proof. Stop on unexpected challenges.

## Comparability

This is8 contact-only production enemies64px around a stationary player at
576,324. Player endurance100000HP is a benchmark-only fixture choice, not game
balance. Seed548 is set globally and each damage RNG is seeded after production
_ready, including player548 and enemies549..556. Production scripts are unchanged.
Warm30 then capture180 physics ticks at configured60Hz. Browser process/RAF
counts can differ while this physics schedule stays the same. The benchmark
checks observed positions,8 living actors and HP/contact progression, and reports
common dependency-directory hashes. Identical seed is not a claim of identical
wall-clock timing. A dependency mismatch must be inspected before calling the
workloads identical. This is NOT production overworld, lair/wave activation,
terrain navigation, spell load, representative worst-case combat or laptopFPS.

Engine monotonic callback intervals and browser RAF intervals use different
clocks and are exported separately. No clamped delta is called frame time.
Snapshots add observer overhead. Renderer object/draw-call counters do not equal
unique nodes drawn. Regions are null/not applicable in this isolated fixture.
Same-machine Chrome ANGLE SwiftShader is software rendering, distinct from the
hosted L40S browser whose blank control was25Hz. Do not combine those results or
calibrate a regression gate from this tiny fixture.

## Default-off boundary

The production main_scene, main.gd, project.godot and root export_presets.cfg
remain unchanged. The browser bridge and Start/Download UI exist only in the
separate benchmark artifact. The production preset excludes tools/*. Only a
temporary copy gets benchmark main_scene/preset; the normal exported game keeps
its original entrypoint. No production query-string or global adapter is added.
Normal source/default export diff and normal no-overlay rendering are checked
separately from benchmark OFF (before explicit Start) and DONE pixels.
